# Заметки для разработки

## Замысел

Неспешная головоломка, вдохновлённая Block Slide, с экспериментальной физикой сцепления и необязательными цитатами. Цитаты выключены по умолчанию. Сейчас используются короткие вольные пересказы древнего «Дао дэ цзин» с указанием главы; при добавлении текстов проверять права на конкретные переводы и не приписывать выдуманные цитаты авторам.

## Версии и запуск

`index.html` — минималистичная игра; `?mode=prototype` — экспериментальный интерфейс. Общие модель и интерфейс находятся в `src/`, отдельной копии физики нет. Игровой режим фиксирует длины 1–4, режим сцепления «выбранный и выше», случайное направление и автоматический ряд после хода. Прототип позволяет переключать правила и скорость падения 0,5–20 клеток/с (по умолчанию 15) и время сгорания 0,6–2 с (по умолчанию 1,2 с). Настройки цитат и озвучки запоминаются в браузере.

Три способа запуска, от простого к гибкому:

1. **Один файл `promezhutok.html`** — игра, стили и код внутри; открывается двойным щелчком, работает офлайн. Сборка: `npm run build` (`scripts/build-standalone.mjs`). Скрипт переносит модули ES в обычный Classic Script с реестром `__modules`: у модулей проекта только статические именованные импорты и нет циклов, поэтому достаточно вычислить их в порядке зависимостей; скрипт переносится в конец `<body>`, потому что классический скрипт выполняется сразу. Манифест и иконки из сборки удаляются: на `file://` установка всё равно недоступна. При появлении `export { … }`, `export default`, динамического `import` или `import.meta` сборка падает — тогда нужен настоящий сборщик.
2. **Двойной щелчок из папки**: `start.bat` (Windows), `start.command` (macOS, Linux — `sh start.command`). Скрипт ищет Node.js, затем Python 3, поднимает сервер и открывает браузер.
3. **Командная строка**: `npm start` (`scripts/serve.mjs`, по умолчанию порт 8000, `--port`, `--open`) или `python3 -m http.server 8000`. Собственный сервер задаёт типы файлов явно: на части установок Windows Python отдаёт `.js` как `text/plain`, и модуль игры не запускается.

Тесты: `npm ci`, затем `npm test` (Node.js 18+; jsdom нужен только для тестов). На телефоне используется адаптивная веб-версия и сенсорное перетаскивание. `manifest.webmanifest` и иконки позволяют добавить страницу на главный экран после публикации по HTTPS; офлайн-режим и нативное приложение не реализованы. `.github/workflows/pages.yml` прогоняет тесты, собирает одиночный файл и готовит статический сайт для GitHub Pages, но сам по себе не включает Pages в настройках репозитория. Ожидаемый URL и шаги публикации — в README.

## Правила и физика

Поле 8 столбцов × 10 рядов, координаты модели с нуля, сверху вниз. Блок горизонтальный и занимает один ряд. Связь возникает при вертикальном контакте с перекрытием хотя бы в одну колонку. Режимы: все связанные блоки либо выбранный и связанные цепочкой вверх.

`src/board.js` отвечает за генерацию, модель, синхронное поклеточное падение и очистку. При перетаскивании `src/drag.js` проверяет непрерывные столкновения тел и отдельных выступов на обеих конструкциях; выступы, вставленные в блок при исходном положении, должны сначала разъединиться вертикально. Нет общего запрета бокового движения по исходной высоте. При попытке пройти через узкую щель призрак мягко выравнивается по сетке, только если это безопасно и увеличивает доступное вертикальное перемещение. При отпускании призрак может вертикально войти в паз, затем положение привязывается к ближайшей достижимой целой клетке. Геометрия выступов берётся из CSS и используется как при рисовании, так и при проверке столкновений; круглое оформление тоже сохраняет видимые верхние выступы. Тестировать сцепление, свободное движение, узкий проход и отсутствие туннелирования.

Очистка всех заполненных строк волны одновременна; свободные конструкции падают синхронными шагами. `resolveBoard` отдаёт кадры, `src/motion.js` объединяет последовательные падения в непрерывную анимацию; линия подсвечивается 400 мс, затем отдельно проигрывается сгорание (по умолчанию 1,2 с). Дождаться завершения Web Animations API, а не только таймера: иначе фазы могут обрываться при запаздывании кадров. По просьбе пользователя падение всегда анимируется, в том числе при reduced motion. Другие виды движения по-прежнему учитывают системную настройку, а очистка при reduced motion обозначается статично. Если после разрешения линии поле пусто, автоматически добавляется ровно один ряд в обоих режимах; автогенерация после хода не должна добавлять второй. Настройка скорости меняет продолжительность визуальной анимации, а не логику. Сброс отменяет прежние кадры и отложенную автогенерацию. Учитывать `prefers-reduced-motion`.

Если верхний ряд был занят перед совершённым ходом и остался занят после его разрешения, игра заканчивается. При автоматической генерации игра также заканчивается, когда после хода невозможно добавить ряд. В ручном режиме при первоначально незанятом верхнем ряде можно продолжить, пока остаётся полезный ход; проверка ходов в `drag.js` использует ту же геометрию выступов. Счёт и баланс предварительные.

**Итог хода считается целиком.** Ход игрока — это размещение конструкции и все волны очистки, которые последовали за ним, включая волну после появления нового ряда и после автозаполнения пустого поля. В `src/main.js` за это отвечает `turn` и `accountResolution`: линии складываются по всем вызовам `animateResolution` хода, комбо берётся максимальным, а цитата за ход показывается один раз. Иначе «одна линия до появления ряда и одна после» давало два отдельных результата по одной линии, и цитата не появлялась. Сообщение при нескольких волнах показывает итог хода, а очки по-прежнему начисляются за каждую волну отдельно (это часть баланса, а не подсчёта цитат).

## Цитаты

`src/quotes.js` — коллекция (`taoTeChing`: короткие вольные пересказы, глава, метки смысла) и распределение. Все тексты — пересказы древнего текста, а не издания чужого перевода; при добавлении проверять права и не приписывать автору выдуманные строки.

**Адаптивное распределение.** Вес цитаты 0..1, изначально все равны 1. Выбор идёт по текущим весам; после выбора веса делают шаг к единице на долю `recovery` (по умолчанию 0,5 — половина оставшегося расстояния), а выбранная цитата обнуляется. Итог: только что показанная не выпадает вовсе, предыдущая имеет половину веса, следующая за ней 0,75 и так далее. История показанного (последние 12) хранится в браузере и воспроизводится при загрузке, поэтому давность сохраняется между сессиями. При `recovery = 0` веса не восстанавливаются, при `recovery = 1` коллекция каждый раз снова равномерна.

**Как мерить близость смыслов (следующий шаг, пока выключен).** У селектора есть параметры `similarity` и `boost`: веса умножаются на `1 + boost · близость(контекст, цитата)`, обнулённый вес при этом остаётся нулевым. Три уровня измерения:

1. `themeSimilarity` — метки, проставленные вручную (Жаккар по множеству меток). Дёшево и предсказуемо, но субъективно.
2. `lexicalSimilarity` — грубая лексическая близость: общие «корни» (первые символы слов) без стоп-слов, Жаккар. Считается без разметки, но ловит совпадения слов, а не смысл; морфологии нет.
3. Семантическая близость — вектор фразы и косинус между векторами. Метрику нужно валидировать: собрать размеченную вручную выборку пар «близко / далеко» и сравнить порядок, который даёт метрика, с человеческим; модель должна укладываться в офлайн-размер игры. Пока метрика не выбрана, `boost` равен 0: кривая давности уже даёт ровное поведение без повторов.

**Озвучка.** `src/speech.js` — обёртка над Web Speech API. Решение: синтез речи, а не готовые аудиодорожки, потому что пользователь сможет добавить свой цитатник без записи звука, а размер игры не растёт; проигрываем зависимость от устройства и отсутствие русского голоса. Поэтому озвучка — настройка, при отсутствии синтезатора цитата показывается текстом, а чекбокс недоступен. Голос выбирается по `ru-RU`, иначе фраза произносится с русской локалью без явного голоса; перед каждой фразой очередь очищается.

**Пословное появление** — `src/reveal.js`. Слова открываются по событиям `boundary` от синтезатора; они приходят не во всех браузерах и не для всех голосов, поэтому у каждого слова есть резервное расписание, которое пересчитывается при каждом событии. При ошибке, остановке и уменьшении движения текст показывается целиком: скрытые слова закрыты только визуально (прозрачность), скринридер читает цитату сразу.

## Рекорды

`src/records.js` и `src/storage.js`. Рекорды (лучший счёт, максимум линий, список лучших партий) пишутся в `localStorage`; если хранилище недоступно (приватный режим, `file://` в части браузеров, тесты без DOM), всё работает в памяти, а игра не ломается. Данные из хранилища проверяются и при мусоре заменяются пустыми. Результат записывается только когда партия завершена, и только в игровом режиме: в прототипе правила настраиваются, поэтому он рекорды показывает, но не пишет (демонстрация анимации тоже не в счёт). Очистка сделана вторым нажатием, а не `window.confirm`: браузерное окно перекрывает игру на телефоне.

## Визуальная проверка и ограничения

Кнопка демонстрации в прототипе сбрасывает партию и создаёт детерминированную сцену с двумя волнами очистки и падением, используя обычный путь разрешения игрового поля. Она нужна для сравнения настроек и наблюдения на устройствах, а не как доказательство комфортного ритма. Помимо модульных тестов полезны запись Performance с кадрами, проверка `requestAnimationFrame`, ручная проверка на телефоне и обратная связь игрока. Headless-браузер, синтетическая нагрузка и отдельные скриншоты не заменяют человеческого наблюдения в реальном времени.

Покрытие тестами: физика и анимация — `tests/board.test.js`, `drag.test.js`, `motion.test.js`; интерфейс — `tests/ui.test.js` (в том числе итог хода через появление ряда, цитаты, озвучка на поддельном синтезаторе, рекорды); отдельные модули — `tests/quotes.test.js`, `records.test.js`, `speech.test.js`, `reveal.test.js`; одиночный файл — `tests/standalone.test.js` (сборка во временный каталог, проверка отсутствия импортов и запуск в jsdom). Проверка записи рекорда при завершении партии через интерфейс не автоматизирована: сценарий «нет полезных ходов» не собирается детерминированно; хранилище и чтение покрыты модульными тестами, а запись при завершении партии стоит проверить вручную.
